# gipr 专用标志核准监管 — 交接底稿

> 接手的人按这份就能上手，不用从头再摸。口径有取舍的地方都定死了，改动同步更新本文。
> 模块代码：`com.fc.v2.service.impl.TGipr*ServiceImpl`，表结构：`doc/schema/gipr.sql`。

## 一、办件流转单 TGiprCaseFlowServiceImpl（state-machine）

- 关次 `stage` 0..3：申请受理 / 材料初审 / 标志核准 / 备案发标；`status` 1 在办、2 已封住。
- **推进一次只挪一档**；挪到第 3 关即封尾，`status` 置 2。
- **封尾判定（新旧库单同尺）**：`status=2` 或 `stage≥3` 都算已办结——早年按旧流程录的
  封顶单（stage 已到 3 但 status 没置 2）同样按办结对待，不再出现"判定跟当年不一样"。
- 已办结的单子：推进、回退、改内容、删除**一律拒**（返回 null / false）。
- 回退一次只退一档（到 0 关为止），不是打回 0 关从头再走。
- 同一动作点两回：越界的第二回被状态机拒掉，留痕里不会多一条有效流转。

## 二、授权签批单 TGiprCertBillServiceImpl（approval-chain）

- 关次 `node_no` 0..2：县级初核 / 市级核认 / 省局核准；`status` 0 在签、1 已点齐、2 已压回。
- 签到：本关应签人数取 `need_count`，未填按算齐办法兜底（两名须同判=2，一名即齐=1）；
  签齐才进下一关、签到数清零；**省局核准（第 2 关）签齐才置已点齐**。
- 否决置已压回；退回一次退一关、签到数清零；首关无可再退。
- **幂等**：只有在签的单子收票/否决/退回；已点齐、已压回的一律拒——同一核准动作
  点两回，第二回落不下。
- 已知边界：同关内"同一个人重复签到"没有签到人名册可判，靠前端防重+状态机守边界，
  真要查得加签到明细表（未建）。

## 三、卷宗转档核收行 TGiprArchiveRowServiceImpl（batch-process）

- 空批次返回 0；超过 500 行返回 -1 且**整批不入库**；批次码以入参 `batchNo` 为准。
- 逐行校验：合法行置已收下入库，非法行（缺授权册代号 / 卷数为空或非正）置已退回
  归入失败明细，**保留原始行号**，返回成功行数——有坏行不拖死整批。
- **幂等**：同一批次码已落过库的，重复递交不再入库，直接返回该批已收下的行数
  （与首次同一口径）。`submitBatch` 方法级 `synchronized` 只保单实例；
  多实例部署需给 `t_gipr_archive_row.batch_no` 加唯一约束兜底（schema 未加，注意）。
- 失败明细 `listErrors` 按行号升序。

## 四、核查提醒条目 TGiprCheckItemServiceImpl（scheduling-job）

- 可处理 = 尚未处理（status 0 或未填）+ 到期。到期线 = 应发日 − 提前量。
- 提前量 `amount`（至多许提前几日）有效窗口 **[2,5] 天**；为空或越窗按 0 天折算到期，
  执行时置**发不成**。
- `runOnce` 逐条落库：发成置已发出、发不成置发不成，返回成功条数；空集返回 0。
  状态落了库，按状态统计与真正发生的操作次数才是同一份账。
- 时段比较统一走墙钟字符串（yyyy-MM-dd HH:mm:ss），不要直接拿 `Date` 当 SQL 参数
  （serverTimezone 不对称会整体偏移，实测踩到）。

## 五、产量换算贴线档 TGiprYieldRuleServiceImpl（rule-eval）

- **可用口径只此一份**（`isEffectiveAt`），列表 / 角标计数 / 旁路 usable / 版本定位
  四处同源：未删（del_flag=0）+ 在位（status 0 或空）+ 生效窗口内
  （eff_start 空或 ≤ at，eff_end 空或 > at，交班当日不含）。
- **同码多版以哪版为准（定死）**：生效窗口内 → priority 大者优先（数值大的先说话）
  → eff_start 晚者优先 → id 大者优先。结果确定，不随查询计划漂。
- 列表排序：priority 降序，并列 ruleCode 降序；`evaluateTop` 取列表首条。
- 分档：阈值未维护的档跳过；**等于上限取高一档**（严格小于才落在本档）；
  三档限值全缺视为不可用返回 0；输入负值越界返回 0（evaluate / evaluateTop 同口径）。

## 六、词条册 TGiprTermBookServiceImpl（与名录底册联动）

- 联动**新增、修改同一把尺**：挂靠的名录产品必须在册（已移出那段不收新行、也不许
  改挂过去）；`prod_no` / `prod_name` 以名录底册为准回写，不留手填口径。
- `lack_num` 轧账：应收录 − 已对齐，负数按 0；新增、修改同一算法（修改时没传的
  字段取库里现值合并重轧）。
- 列表查询用调用方传入的条件、只统一兜 `del_flag=0`，分页由 controller 的
  `startPage()` 负责——明细与分页统计同源，服务层不再另起一页、不再暗加状态过滤。

## 七、本次毛病对照（现象 → 根子 → 落点）

| 现象 | 根子 | 落点 |

| 该锁死的还能编辑保存 | updateContent 没看办结标记 | 一 |

| 同一批递两回重复入库 | submitBatch 无批次判重 | 三 |
| 坏行拖死整批/空批炸/超限不拦 | 校验后合法行不入库、get(0)、MAX_ROWS 没用 | 三 |
